## 引言：Agent 不是 ChatBot + 工具

- 钩子：同一个 GPT-4，SWE-bench 3.8% → 49%，区别不在模型
- Agent 的本质问题：在开放环境中持续完成目标
- 这是一个控制论问题，不是一个对话问题
- 引出四层闭环：感知 → 决策 → 行动 → 反馈 → 感知...
- 与经典控制系统的类比：传感器、控制器、执行器、反馈回路

来源：SWE-agent, CoALA

## 1. 全局框架：CoALA 与四层闭环

### 1.1 CoALA 的形式化

- 记忆：工作记忆（上下文窗口）+ 长期记忆（程序性/语义性/情节性）
- 动作空间：内部动作（推理、检索、写入记忆）+ 外部动作（工具、环境交互）
- 决策过程：从动作空间中选择下一步

### 1.2 四层映射

| 层 | CoALA 对应 | 核心问题 | 工程实现 |
|---|-----------|---------|---------|
| 感知 | 工作记忆输入 | 模型看见什么 | 观察格式、上下文管理 |
| 决策 | 决策过程 | 下一步做什么 | 规划、推理链、搜索 |
| 行动 | 外部动作 | 对环境做什么 | 工具调用、代码执行 |
| 反馈 | 观察 → 记忆更新 | 做对了吗 | 验证、反思、记忆更新 |

### 1.3 Workflow vs Agent

- Workflow：编排型，预定义代码路径（确定性）
- Agent：自主型，模型动态决定路径（灵活性）
- 决策原则：从最简方案开始，仅在复杂度证明必要时升级到 Agent

来源：CoALA, Anthropic

## 2. 感知层：模型能看见什么

核心矛盾：上下文窗口有限 vs 环境信息无限

### 2.1 观察格式设计（Agent-Computer Interface）

- SWE-agent 实验：同模型，改接口设计，3.8% → 12.5%
- 设计原则三条：
  - 最小认知开销（模型训练数据中自然出现的格式）
  - 先给上下文再要求精确输出
  - Poka-yoke 防错设计（绝对路径消灭相对路径错误）
- 实例：文件查看器（分页 vs 全量）、搜索命令（结构化输出 vs 原始 grep）

### 2.2 记忆架构

- 三层模型（Lilian Weng）：
  - 感知记忆 → 原始输入的第一层处理
  - 短期记忆 → 上下文窗口（快但有限）
  - 长期记忆 → 向量库/文件系统（大但慢）
- 工程实现：
  - RAG（语义检索）
  - Filesystem as Context（文件系统即外部记忆）
  - Variables Manager（显式状态追踪）

### 2.3 上下文管理的工程策略

- 上下文腐化问题："Lost in the Middle" — 中间位置信息被忽略
- 40% 阈值：上下文超过窗口 40% 后性能急剧下降
- 五种策略：
  1. 压缩（摘要化历史）
  2. 观察遮蔽（隐藏旧工具输出）
  3. JIT 检索（按需拉取，不预加载）
  4. 工具输出卸载（大输出写文件，上下文只保留摘要）
  5. 注意力工程（关键内容放首尾）

来源：SWE-agent, Lilian Weng, Agent Patterns Atlas

## 3. 决策层：模型怎么选择下一步

核心矛盾：搜索空间指数爆炸 vs 计算预算有限

### 3.1 执行循环的演化谱系

三代循环，复杂度递增：

| 代 | 方法 | 循环结构 | 代价 | 适用场景 |
|---|------|---------|------|---------|
| 1 | ReAct | Thought → Action → Obs | 低 | 单步推理+行动 |
| 2 | Reflexion | 执行 → 失败 → 反思 → 重试 | 中 | 需要从失败中学习 |
| 3 | LATS | MCTS搜索树 + LLM评估函数 | 高 | 高价值复杂决策 |

- ReAct：显式推理轨迹消除幻觉（HotpotQA 幻觉率 56% → ~0%）
- Reflexion：语言反馈存入 episodic memory（HumanEval 67% → 91%）
- LATS：MCTS + 自反思 + 环境反馈（HumanEval 92.7%）

### 3.2 任务分解策略

- 层级分解：Orchestrator-Workers（中心 LLM 拆任务、分配、合并）
- 极端分解：每步只做一件最小可验证的事
- 自动课程：Voyager 的开放式目标生成（不需要预定义任务列表）
- Routing：输入分类 → 不同处理路径

### 3.3 规划的工程权衡

- 简单任务：ReAct（一次 LLM 调用 = 一步决策）
- 中等任务：Prompt Chaining（固定步骤，确定性）
- 复杂任务：Orchestrator-Workers（动态分解）
- 高价值任务：树搜索（多路探索，回溯）
- Anthropic 原则："从最简单方案开始，只在复杂度证明必要时升级"

来源：ReAct, Reflexion, LATS, Voyager, Anthropic, Agent Patterns Atlas

## 4. 行动层：模型能对环境做什么

核心矛盾：能力越强越容易出错（工具越多，误选率越高）

### 4.1 工具设计原则

- Anthropic 核心洞察：花在工具设计上的时间 > 花在 prompt 上的时间
- 五条原则：
  1. 用模型训练数据中自然出现的格式
  2. 名称 = 动词+名词，描述 = 给初级开发者的文档
  3. 包含示例、边界、失败行为
  4. 防错设计（强制绝对路径、参数枚举）
  5. 工具之间边界清晰（何时用 A 而非 B）
- 反模式：工具 >30 个后准确率下滑；改用动态加载 Top 5-10 → +30%

### 4.2 动态工具管理

- 静态全量暴露（简单，但工具多了会崩）
- 动态加载：按任务阶段暴露相关子集
- Skill Discovery：Agent 运行时自行发现可用工具
- Voyager 技能库：执行成功的代码片段自动入库，下次可复用

### 4.3 行动的安全边界

- 沙箱执行（隔离文件系统、网络）
- 权限最小化（Constrained Tool Use）
- 不可逆操作前人类确认
- Handoff：Agent 之间的控制转移（OpenAI SDK）

### 4.4 代码即行动

- Voyager 的洞察：用可执行代码替代 JSON 工具调用
- 优势：组合性更强、可验证、可存入技能库
- 风险：需要严格沙箱

来源：Anthropic, SWE-agent, Voyager, Agent Patterns Atlas, OpenAI Agents SDK

## 5. 反馈层：模型怎么知道做对了

核心矛盾：即时反馈浅层但便宜 vs 深层反馈有价值但贵

### 5.1 反馈信号的层次

| 层次 | 来源 | 延迟 | 可靠性 |
|-----|------|------|-------|
| 执行反馈 | 工具返回码/编译器输出/测试结果 | 即时 | 高（确定性） |
| 环境反馈 | 状态变化观察 | 短 | 中 |
| 评估反馈 | LLM-as-Judge | 中 | 中（有偏） |
| 反思反馈 | 自我语言反思 | 长 | 低（可能过度纠正） |

### 5.2 验证机制

- 规则验证：测试、Linter、类型检查（确定性，成本低）
- 视觉验证：截图对比（UI 任务）
- 语义验证：独立 LLM 评估（开放式任务）
- Evaluator-Optimizer 模式：一个生成、一个评估、迭代改进

### 5.3 自我反思机制

- Reflexion：失败 → 写反思 → 存入 episodic memory → 下次避免
- 反思的风险：模型被告知"double-check"时，58% 情况下翻转正确答案
- 工程实践：
  - 限制反思次数（最多 2-3 次）
  - 区分"信心低"和"确认出错"
  - 用外部验证（测试）而非纯内省

### 5.4 错误恢复

- AgentDebug：定位根因（记忆错误/推理错误）→ 从失败点重跑 → +26%
- 错误分类：
  - 瞬态错误 → 重试（指数退避）
  - 语义错误 → 换策略（改 prompt、降级模型）
  - 不可恢复 → 升级到人类
- VIGIL：运行时监控 → 诊断 → 自动修复 prompt/代码

### 5.5 人机协作检查点

- 何时交给人：高风险操作、信心低、不可逆
- Human-in-the-Loop 不是"兜底"，是架构的一部分
- Red-Flagging：检测到异常主动升级

来源：Reflexion, AgentDebug, VIGIL, Agent Patterns Atlas, Anthropic

## 6. 四层耦合：层间如何互相影响

用一个完整示例（代码修复 Agent）走一遍四层循环：

1. 感知：读取 GitHub Issue + 相关代码文件（ACI 设计决定能看到什么）
2. 决策：分析问题 → 选择修复策略（ReAct 循环）
3. 行动：编辑文件 + 运行测试（工具调用）
4. 反馈：测试失败 → 反思原因 → 回到感知层重新读取（Reflexion）
5. 第二轮：感知更新（把反思存入记忆）→ 决策调整 → 行动修正 → 测试通过

关键耦合关系：

- 感知 × 决策：观察格式直接影响推理质量（SWE-agent 证明）
- 决策 × 行动：规划粒度必须匹配工具粒度（太细的计划配太粗的工具 = 无法执行）
- 行动 × 反馈：工具返回格式决定反馈的可用性
- 反馈 × 感知：反思结果写入记忆，改变下一轮的感知内容

来源：综合

## 7. 工程实践 Checklist

### 7.1 架构选择决策树

```
任务是否有固定步骤？
├── 是 → Workflow（Prompt Chaining / Routing / Parallelization）
└── 否 → 步骤数是否可预测？
    ├── 是 → Orchestrator-Workers
    └── 否 → Agent（自主循环）
        └── 需要从失败中学习？
            ├── 是 → 加 Reflexion
            └── 高价值决策？→ 加 LATS
```

### 7.2 四层设计清单

感知层：
- [ ] 观察格式是否用了模型熟悉的格式？
- [ ] 长期记忆是否有检索机制？
- [ ] 上下文是否有压缩/裁剪策略？
- [ ] 关键信息是否放在首尾？

决策层：
- [ ] 循环结构是否匹配任务复杂度？
- [ ] 是否有任务分解（避免一步做太多）？
- [ ] 是否有终止条件（最大轮次 + token 预算）？

行动层：
- [ ] 工具定义是否包含示例和边界？
- [ ] 工具数量是否控制在合理范围？
- [ ] 是否有沙箱隔离？
- [ ] 不可逆操作是否有确认机制？

反馈层：
- [ ] 是否有确定性验证（测试/编译）？
- [ ] 反思机制是否有次数限制？
- [ ] 错误是否分类处理？
- [ ] 是否有人类升级路径？

### 7.3 常见坑

| 坑 | 症状 | 修复 |
|---|------|------|
| 感知过载 | 模型忽略关键信息 | JIT 检索 + 注意力工程 |
| 规划过深 | 计划完美但执行偏离 | 用 ReAct 替代长期规划 |
| 工具过多 | 误选率飙升 | 动态加载 Top 5-10 |
| 反思过度 | 翻转正确答案 | 限制 2-3 次 + 外部验证 |
| 无终止条件 | 无限循环 | 双重保险：轮次 + token |
| 反馈缺失 | 错误累积不可逆 | 每步验证 + 检查点 |
